# Integer capacity allocation v1

为离线供需规划者把合成有向网络的供给、需求和链路上限转成最大可服务量，提供流与最小割证书。
不是地形汇流、最短路或物料来源追溯。输入nodes为唯一标识，links每项id/from/to/capacity，
supplies/demands每项node/amount。全部量是同一规划周期内整数单位，0..10^9；没有隐含时间换算。
节点<=100、链接<=500，源/需求每类<=100。同节点不可重复供给或需求，供需节点集合不交叠。
允许平行边、反向边与环，链路ID唯一；自环、未知引用与__前缀节点拒绝。空供需合法。

添加超级源汇，把供给和需求当上限，以Edmonds-Karp增广最大流。反向残余弧按每条边独立保存，
不会把真实反向管线与算法撤回流量混为同一边。边按ID、供需按节点排序，保持确定性。
不模拟压力、流速、水损、泵耗、管网物理或真实供水方案。

## 分配模式

CLI用 `--allocation max-flow|fair` 选择，缺省 `max-flow`；Python API 为
`analyze(data, allocation='max-flow'|'fair')`。

- max-flow（缺省，保留原逻辑与原报告字段）：仅最大化总服务量，不保证公平、最低成本、
  优先级或唯一解；需求间分配可能受确定顺序影响。
- fair：三级词典序目标，全部在同一整数容量边界内完成，不放宽任何容量：
  1. 先最大化总服务量，与 max-flow 的最优总量完全相同；
  2. 再最大化所有正需求节点的最小满足率 served/amount，比率用精确整数分数比较，
     零需求节点不参与比率；没有任何正需求时比率定义为 1；
  3. 仍并列时，按需求节点名升序，把服务向量逐分量词典序最大化。

公平模式的实现只用带上下界的整数可行流（超级源/汇环流归约）与同一个 Edmonds-Karp，
辅以精确整数二分；不逐单位枚举容量，不引入第三方优化器。比率输出为约分后的
`min_service_ratio: {numerator, denominator}`，并额外输出 `allocation_mode: "fair"`；
max-flow 模式不含这两个字段，其余字段两种模式完全一致。链路流本身可能不唯一，
但同一输入结果确定，输入数组任意重排不改变报告。

## 输出与证书

输出每条原链路流量、每源使用、各需求服务和缺口、剩余残余可达节点与最小割边。
cut_edges包括供给/需求人工边，不能把它们都叫物理瓶颈。校验每边容量、原节点流量守恒，
且割容量=总服务量。公平模式沿用 max-flow 同一残余可达集与最小割证书字段，
因此证书仍证明该线性容量模型下总量的最优性，不表示现实系统最优。
样例供给10、需求9，经L1瓶颈只能服务7；max-flow 为 east=4/west=3，缺口west=2，割容量7；
fair 总量仍为7，但重排为 east=3/west=4，最小满足率精确为 3/4，证明公平目标在不损失
最大总量的前提下改变了分配。

当前静态整数单商品流，无多商品、时段调度、随机故障仿真或交互式运营服务。
